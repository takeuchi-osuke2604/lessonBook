## 依頼文
「小さな習い事の教室をやっています。生徒には月の初めに通う日を予約してもらい、紙の出欠表に書いています。急な欠席の連絡を電話やメッセージでもらっても、紙に書き忘れて、来ない生徒を待ってしまうことがあります。紙をやめて、その日に来る人をすぐ確かめられるようにしたいです。」

## 前提
- サーバやログインは使わず、教室に置いたタブレット1台のブラウザの中で完結させる
- 生徒からの連絡は、これまでどおり電話やメッセージで先生に届く。ページを操作するのは先生だけとする
- 解決する対象は「連絡を受けたその場ですぐ記録でき、当日に来る人をひと目で確かめられること」とする

## 要件
### 1. 予約管理（登録・削除）
- 先生が「予約管理（一括予約）」画面に切り替えて予約の入力・変更を行える。
- 予約管理では対象月を切り替えて、任意の日付に対して予約を登録・変更できる。
- 予約の入力方法は以下の2種類を用意する。
    - 日付に対して生徒を選択（複数可）して行う。
    - 生徒に対して対象の月の日付を選択（複数可）して行う。
- チェック状態を変更後、「保存」ボタンを押すことで予約内容を確定する。
    - 保存前に画面を離れた場合は変更を破棄する。
- 同じ生徒を同じ日に重複して予約できない。

### 2. 日々の出欠管理
- デフォルトで「本日の出欠」画面を表示し、画面上に常に現在の日付を表示する。
- 予約をした時点で「出席予定」に分類される。
- 習い事のある日の予約者について、「出席予定」と「欠席」の一覧を別々に表示する。
- 急な連絡を受けた際、ワンタップで「出席予定」から「欠席」の欄に移動できる。
- 押し間違えた際、ワンタップで「欠席」から「出席予定」の欄に戻すことができる。
- 出欠画面では予約の削除は行わない。
- 日付を切り替えて、過去・未来の予約と出欠を確認・変更できる。
- 当日の表示の下に「明日の予定」を表示する。
    - 明日の予定には、明日予約されている生徒名と人数を表示する。
- 予約が0件の場合は「本日の予約はありません」と表示する。

### 3. システム・動作環境
- ブラウザを再読み込みしても、予約と出欠データがそのままlocalStorageに保持される。
- 生徒名はすべて架空の名前にする。
- タブレットの幅（768px）に対応し、横スクロールが発生しない。

## 確かめ方（テスト手順）

| 手順 | 操作内容 | 期待される結果 |
| :--- | :--- | :--- |
| **1. 初期表示確認** | アプリを開く | デフォルトで本日の日付が表示され、「出席予定」「欠席」の2つの欄および画面下部に「明日の予定」が表示されていること。 |
| **2. 休校日の表示確認** | 予約が存在しない日付を選択する | 「本日の教室はありません」等のメッセージが表示されること。 |
| **3. 予約登録（パターンA）** | 「予約管理」へ移動し、「日付 → 生徒（複数）」でチェックを入れて保存する | 出欠画面の該当日に、選択した生徒が「出席予定」として反映されていること。 |
| **4. 予約登録（パターンB）** | 「予約管理」へ移動し、「生徒 → 月の日付（複数）」でチェックを入れて保存する | 出欠画面の該当日に、対象生徒が「出席予定」として反映されていること。 |
| **5. 予約削除** | 登録済みのチェックを外し、保存する | 出欠画面から該当生徒の予約が削除されていること。 |
| **6. ワンタップ欠席操作** | 出欠画面で「出席予定」の生徒ボタンをタップする | 対象生徒が即座に「欠席」欄へ移動すること。 |
| **7. ワンタップ復帰操作** | 「欠席」欄にいる生徒のボタンをタップする | 対象生徒が即座に「出席予定」欄へ戻ること。 |

| **9. 画面幅テスト** | 開発者ツール等で画面幅を 768px に設定して操作する | 横スクロールが発生せず、すべてのボタン・文字が収まって操作できること。 |
